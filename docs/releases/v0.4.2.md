# PDF Markup 0.4.2

Undo/redo now changes only highlight strokes. Creating, deleting, or moving a
highlight adds a history step; changing color, width, rounding, categories, or
other settings does not. Shapes, text, measurements, and page legends remain
applied when undoing highlights. Highlight movement keeps the latest appearance,
and setting changes preserve redo. Category locks remain effective; restoring
a highlight cannot recreate a deleted category or overwrite another object's ID.

The highlighter preview's dashed circle now shrinks with its colored dot down
to very thin widths. Both use the actual stroke thickness at the current zoom.

The transitive build dependency `source-map-js` is updated to 1.2.2 to address
[GHSA-68fv-2mgg-jv7q](https://github.com/advisories/GHSA-68fv-2mgg-jv7q).

## Install and compatibility

Download `pdf-markup-tool_0.4.2_x64-setup.exe` and `SHA256SUMS.txt` from this
release. Windows 11 x64 is the locally tested platform. Node.js and Rust are
not required; WebView2 is downloaded if missing. Normal editing works offline.
The app retains its current-user installation and existing identifier.
Back up projects before upgrading. Project formats and native permissions are
unchanged; portable projects still include the source PDF.

See the [user guide](https://github.com/rojerm2/markup-tool/blob/v0.4.2/docs/USER_GUIDE.md)
for the updated history behavior and existing features.

## Verification and limits

Release checks cover highlight history and property preservation, mixed bulk
edits, locks, stale gestures, preview sizing, project save/dirty behavior, the
full frontend/Rust suites, formatting, lint, type checks, dependency audits,
license provenance, and installer packaging. Desktop checks cover the changed
history and preview behavior in the packaged app.

Input/export limits remain 256 MiB for PDFs and 16 MiB for annotation metadata.
Projects and local recovery files are not encrypted; markup is not secure
redaction. Measurements depend on calibration, and comparison is a visual aid.
Upstream Windows Unicode dependency maintenance warnings are documented in the
[security policy](https://github.com/rojerm2/markup-tool/blob/v0.4.2/SECURITY.md).
Signature status is recorded below by the release workflow. Installation on
another computer depends on Windows, WebView2, and organizational policies.
